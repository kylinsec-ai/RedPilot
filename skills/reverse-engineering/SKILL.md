# 二进制/固件逆向与校验绕过(f2 类)

拿到可执行文件(可能在 /work 的题目录、随题下发或从目标下载):目标=让程序吐授权凭据/通过校验/发现隐藏指令。

## 0. 起手式(文件与运行环境)
- `file`、`strings -n 6`(先扫可见线索:flag 格式、提示串、报错串)、`checksec`(pwntools 内置)
- 架构不是本机(x86_64)的 ELF:`qemu-<arch> ./prog`(qemu-user 已装,支持 arm/mips/aarch64 等),必要时 `qemu-<arch> -strace` 看系统调用
- 需要输入时先看 usage/help 输出形态;找不到输出就 ltrace/strace 观察

## 1. 动态优先(校验逻辑大多能被旁路观察)
- `ltrace -e strcmp,strncmp,memcmp,strlen,atoi,printf -s 200 ./prog`——**输入与正确值对比的瞬间直接泄漏预期串**(最快路径,license/序列号题经常一发入魂)
- `strace -f -s 200 ./prog`:文件读取(读 key/flag 文件路径)、网络行为
- gdb:在 cmp 处断(`break strcmp`/按地址),观察参数与返回;`gdb -batch -ex 'b *main+off' ...` 脚本化
- 输入藏文件里反复试:`ltrace ./prog < in.txt`;正确值若在内存比较中,动态改跳转:`gdb` 改 `$eflags`/`set {char}addr=...`

## 2. 静态分析
- r2 快速流:`r2 -A ./prog` → `afl` 列函数、`s main; pdf` 看主逻辑、`iz` 字符串、`axt` 交叉引用到校验函数
- 校验形态识别:
  - 明文比较(字符串/固定表)→ 直接读出
  - 算法校验(MD5/SHA/自研 hash/CRC)→ 逆出输入条件或爆破(短输入用 z3/穷举,见下)
  - 查表/编码(自研"内部执行机制")→ 逐指令理解字节码/表驱动逻辑
  - 反调试/反逆向(时间检查、ptrace、自修改、混淆 VM)→ 优先动态绕:改时间/剥离检查分支;VM 类先找 dispatcher 与 opcode 表
- 符号/调试信息残留在就幸福:`nm`、`readelf -s`;去符号就 `r2 -A` 启发命名

## 3. 出凭据的路径
- 程序输出了加密/编码的凭据与"授权码/序列号"绑定 → 理解算法后**自己生成合法输入**(keygen),或找到隐藏的"正确口令"直接输入
- 未公开命令(命令处理接口题):strings/函数表找命令字符串,试 `help` 列出的之外名字(大小写、缩写、版本号拼接)
- flag 常在程序内存/文件系统:动态运行到校验通过点,看它读哪个文件/打哪块内存

## 4. 计算辅助
- z3 解约束:`python3 -c "from z3 import *"` 写约束求输入;短 key/序列号校验逻辑明确时比纯穷举快
- 穷举/暴力:输入空间小时直接循环喂(程序本地运行,快);`ropper` 找 gadget 仅在需要构造 ROP 时用

## 纪律
- 每次改动(输入/补丁)前后保存原始文件副本(`cp prog prog.orig`)
- 题面给的模块名/格式提示(如"序列号 8 位十六进制")先解析成约束,别盲试
