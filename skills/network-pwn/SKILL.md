# TCP 行协议服务内存漏洞(f1 类)

服务是**自定义 TCP 行协议**(每条命令一行文本/可含二进制),漏洞在服务端 C/Rust 实现里。目标:让服务把内存中受保护的 flag 读出来。

## 1. 协议建模
- 逐条命令试:help/状态类命令先拿全命令面;每条命令的参数格式、长度限制、回显结构
- 观察**回显泄漏**:错误消息是否带地址/长度/内容;越界参数(超长、负数、0、极大)回显差异
- 用 pwntools 交互模板:
  `python3 -c "from pwn import *; r=remote('TARGET',PORT); r.sendline(b'...'); print(r.recvall(timeout=2))"`(无交互 tty 时用脚本文件更稳)

## 2. 按题面漏洞类型试
- **回显数据超边界(heartbeat 型)**:设载荷后请求"按给定长度回显"——长度参数大于实际载荷 → 越界读,逐步加大请求长度把服务端内存(flag 在附近堆/全局区)带出来;先小步探稳定偏移
- **格式化字符串**:命令参数若被当格式串(sendline 前先试 `%p.%p.%p.%p`/`%s`),直接 `%n$x` 布局泄漏与写;flag 常在堆上,先栈泄漏找地址再读
- **按偏移写入(任意写提示)**:支持"按偏移写入数据/导出缓冲区/查看状态" → 理解内部缓冲区布局(头结构+数据区),负偏移/越界偏移写头字段(长度、指针、状态标志),改完用导出命令读出受保护区
- **整数/长度混淆**:负数长度、`0-1` 下溢、单位混淆(bytes vs 条目)
- **LRU/缓存语义缺陷**:容量淘汰、过期、键名冲突、历史查看命令泄漏已删值

## 3. 工程化
- 每个原语(写/读/状态)先做**无害探测脚本**留档,记录偏移与响应长度映射
- 目标拿到 flag 的方式通常是**读**,不是弹 shell——先全力读泄漏,别急着 RCE
- 复现脚本保持单文件,标注每个 magic 值的推导,方便失败时回头改偏移
